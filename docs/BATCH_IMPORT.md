# 批量时刻入库

在数据管理选择已解析文件，下方“批量时刻入库”提供：UTC起止时间、每N个源时刻选择1个、选择全部、批量提交、失败重试、取消排队任务，以及同文件时间范围分析链接。

## 使用规则

- 间隔1选择范围内连续源时刻，间隔6每6个源时刻选1个；不会创造不存在的时间。范围包含首尾，间隔从范围内首个时刻开始计数。
- 单次1–256个时刻，全局最多512个排队/处理中任务。超限整批拒绝，不部分入库、不静默截断。
- 数据库按文件+时间索引唯一，成功、排队、处理中任务跳过；失败/已取消的任务沿用原ID重新排队，不覆盖成功产物。
- 后台串行转换，真正取得执行机会才标“处理中”；文件解析也共用执行锁。页面每3秒更新状态，离开页面不会取消服务器任务。
- “取消所选排队任务”只取消当前选择范围里的queued任务。processing安全完成，ready保持不变。
- 服务重启后queued继续处理，processing标为中断失败，用户可重试；cancelled不会自动恢复。
- 总进度是当前选择时刻的处理进度，失败/取消计入已结束，成功数单列；不是独立批次历史。
- “分析此时间范围”传递datasetId/start/end UTC到时空分析，未入库的相邻时刻仍留空。

## 技术范围

复用现有IonosphereImport表，无新表或外部队列依赖。`POST /datasets/{id}/imports/batch`和`POST /datasets/{id}/imports/cancel`接收`{timeIndices:[...]}`，复用认证与所有者隔离。单时刻接口兼容原有返回格式。仅支持当前单API进程部署；不支持多个API进程共享此内存执行锁。
