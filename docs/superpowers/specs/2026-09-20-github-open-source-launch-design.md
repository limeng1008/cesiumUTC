# CesiumUTC GitHub 开源发布设计

## 目标

将现有 CesiumUTC 项目打造为可安全公开、可复现运行、能在十秒内传达价值的 GitHub 开源项目，并发布到 `https://github.com/limeng1008/cesiumUTC.git`。

项目定位为：

> CesiumUTC —— 开源三维电离层分析与科学可视化平台。

## 呈现策略

采用“科技作品集”方向，兼顾视觉吸引力和工程可信度。

README 首屏按以下顺序组织：

1. 项目名称、一句话价值说明和中英文入口。
2. 构建、许可、Python、Vue、Cesium 等状态徽章。
3. 一张横向主视觉截图，首选山东区域多高度切片场景。
4. 紧接一个轻量动态演示，展示操作而非重复静态画面。
5. 功能亮点、架构、快速启动、数据契约、测试、路线图和贡献入口。

README 英文版为 GitHub 默认入口，中文版作为次级语言入口并保持结构对齐。社区文件、GitHub 模板、CI 名称和仓库描述均使用英文。

## 媒体设计

### 截图

截图用于表达静态结果和页面全貌。优先收录：

- 山东区域多高度电离层切片，作为 README 主视觉。
- 全球电离层概览。
- 时空分析或数据分析中最具信息量的结果页。
- 数据管理与 SAMI3 数据导入页面，仅在其能表达项目闭环时保留。

截图不包含本地绝对路径、账号、令牌、真实私有数据集标识或其他敏感信息。

### 动态演示

制作一个 20–30 秒的无声短演示，包含：

1. 旋转或切换地球视角。
2. 切换单高度和多高度切片。
3. 点击空间探针并展示数值。
4. 绘制沿线垂直剖面或展示时间变化。

README 使用压缩后的动画预览以保证加载速度，同时提供高清 MP4 文件链接。如果录制环境无法稳定输出动画，则以有次序的三张操作截图替代，不用低质量动画凑数。

## 产品界面收尾

发布前完成已确认的两处界面修正：

- 移除三维地图左下角的“多高度切片 / WGS84 / 区域”三行信息叠层。
- 修正较矮窗口中中央地图、图例和状态栏超出可视区域的布局问题。桌面端地图允许根据可用高度收缩，移动端仍保留可操作的最小高度。

修正不改变 Cesium 场景交互、切片数据、探针数值或地图署名。

## 开源安全与仓库卫生

公开提交必须排除：

- SQLite 数据库及其 WAL/SHM/备份文件。
- 科研数据集、NetCDF 源数据和导入临时文件。
- `.env.local`、真实令牌、密钥、密码和机器专用配置。
- 虚拟环境、`node_modules`、构建产物、测试缓存、浏览器录制产物和本地规划文件。

入库前执行跟踪文件清单、大文件和常见凭证模式检查。示例配置仅包含无密钥的本地开发默认值。

## 工程与社区文件

仓库将补齐：

- 重写后的英文默认 `README.md` 和中文 `README.zh-CN.md`。
- `CONTRIBUTING.md`、`SECURITY.md`、`CODE_OF_CONDUCT.md` 和 `CHANGELOG.md`。
- GitHub Issue 模板、Pull Request 模板和自动化测试工作流。
- 必要的示例配置、种子数据说明与故障排查入口。

工作流至少验证 Python 后端测试、前端类型检查和前端测试。若现有测试依赖本地私有数据，必须改用可提交的最小模拟数据或明确分组，不允许 CI 静默跳过核心验证。

## 许可与归属

## 发布与验收

发布顺序：

1. 完成界面收尾和开源文件。
2. 生成并压缩截图与动态演示。
3. 运行后端、前端和构建验证。
4. 执行敏感文件、大文件与 Git 跟踪清单审计。
5. 创建干净提交并推送到 `limeng1008/cesiumUTC` 的 `main` 分支。

验收条件：

- GitHub 首页能在首屏看到定位、主视觉和快速启动入口。
- 新用户能按文档启动项目或获得明确的缺失依赖提示。
- 公开 Git 树中无数据库、私有数据集、凭证或本地缓存。
- 已确认的界面问题在常见桌面尺寸和较矮窗口中均已修复。
- CI 配置与本地验证命令一致。
